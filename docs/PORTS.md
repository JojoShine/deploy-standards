# 端口与路由约定

应用容器统一监听 `0.0.0.0:8080`。宿主机对 Web 服务分配 `31000–31999`，仅发布到回环地址；公网请求由宿主机 Nginx 转发。

```yaml
ports:
  - "127.0.0.1:${APP_PORT}:8080"
```

`0.0.0.0` 是容器内监听地址，`127.0.0.1` 是宿主机绑定地址，二者用途不同。不能把宿主机映射简写为 `${APP_PORT}:8080`，该写法可能扩大暴露范围。参考：[Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)。

| 服务类型 | 容器端口 | 发布宿主机端口 |
| --- | --- | --- |
| Web app | `8080` | `127.0.0.1:<分配值>:8080` |
| worker | 无 HTTP 接口时不需要 | 无 |
| migrate/bootstrap | 无 | 无 |
| PostgreSQL | 使用外部服务地址 | 生产 Compose 不启动或发布数据库 |

每个业务、环境占用独立宿主机端口；同一业务升级保持端口不变。多环境共用主机时，除端口外也要隔离目录和数据库；默认 `/opt/<business>` 只对应一个部署环境，不要在同一目录交替部署多个环境。

运维应在主机资产记录中维护以下表格。此表为格式示例，`31001` 不代表已经在任何服务器预留：

| 业务 | 环境 | 宿主机 | 端口 | 域名配置标识 | 路径前缀 | 负责人 |
| --- | --- | --- | --- | --- | --- | --- |
| `sample-survey` | `production` | 项目记录 | `31001` | `example-com` | 空 | 项目记录 |

分配前同时查看登记记录和当前监听，避免占用已有端口；先在服务器 `.env.prod` 设置 `APP_PORT`，再让 Nginx 上游指向同一值。超出默认范围时在业务仓库记录原因和验证方式，不静默修改通用脚本。

宿主机的业务片段路径为：

```text
/etc/nginx/business/<domain-id>/<business>.conf
```

例如 `domain-id=example-com`，由对应域名的 server block include 该片段。片段内配置 `location` 和 `proxy_pass http://127.0.0.1:<APP_PORT>`；域名、TLS 和 include 由主机现有配置管理。需要保留 `BASE_PATH` 时，示例的 `proxy_pass` 不加会剥除前缀的 URI 尾斜杠，实际行为必须通过项目路由测试确认。

Nginx 修改先通过配置检查，再按主机运维流程加载。共享部署脚本不负责创建目录、证书、开放防火墙或覆盖 Nginx 配置。
